## 배경

팀의 업무 요청은 대부분 Slack 메시지와 스레드로 들어왔습니다. 형식이 정해져 있지 않아 일부는 빠지고 일부는 중복됐고, 누가 맡았는지·어디까지 처리됐는지 한눈에 볼 수 없었습니다. 요청이 늘수록 담당자가 메시지를 계속 다시 확인해야 하는 구조였습니다.

## 내가 한 일

- **정의** — 하나의 업무 요청으로 관리해야 할 정보를 요청자·담당자·업무 내용·상태·우선순위로 정리하고 MySQL 스키마를 설계했습니다.
- **도구 선택과 설득** — Zapier와 Integrately를 비용, 트리거 제한, 액션 유연성 기준으로 비교했습니다. 직속 이사와 팀원 앞에서 발표해 도입 승인을 받았습니다.
- **구축** — Integrately로 Slack → MySQL 자동 적재 흐름을 만들었습니다.
- **내재화** — 외부 서비스에 계속 기대지 않도록 Python과 Slack API로 수집·정제·적재를 직접 구현해 전환했습니다.
- **확산** — 누구나 같은 방식으로 쓸 수 있게 사용 가이드와 오류 대응 문서를 만들었습니다.

## 결과

- 메시지를 일일이 확인하던 방식에서 **요청 현황을 데이터로 관리**하는 방식으로 전환
- 누락·중복 문제 해소, 관리자가 우선순위를 DB에서 바로 확인
- 사내 구현으로 **외부 SaaS 비용 제거**

## 배운 점

자동화에서 중요한 것은 도구가 아니라 **반복되는 일을 어떤 단위로 정의하고, 어디까지 자동화하고 어떤 예외를 사람이 판단할지 설계하는 일**이라는 것을 배웠습니다. 이 경험이 이후 MDA 플랫폼으로 이어졌습니다.
