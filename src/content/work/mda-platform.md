## 배경

경영데이터팀은 여러 부서가 쓰는 계약·환불·프로모션 데이터를 Google Spreadsheet로 관리하고 있었습니다. 데이터가 쌓이면서 조회에 평균 12초가 걸렸고, 사람이 직접 옮겨 적는 과정에서 누락과 중복이 생겼습니다. 현업은 필요한 자료가 있을 때마다 데이터팀에 요청했고, 양쪽 모두 같은 일을 반복하고 있었습니다.

단순히 속도를 높이는 것보다 **현업이 필요한 정보를 스스로 꺼내 쓰는 구조**가 필요하다고 판단했습니다.

## 내가 한 일

- **요구사항 정리** — 실무 부서 실장 4명을 인터뷰해 어떤 데이터를 어떤 판단에 반복해서 쓰는지 확인했습니다. 부서마다 목적이 달라, 하나의 거대한 표 대신 목적별로 원천 데이터를 1차 분리했습니다.
- **파이프라인** — 목적별 Redash SQL 쿼리 6개를 설계하고, 각 데이터에 맞는 Python 전처리 스크립트를 작성해 MySQL에 자동 적재되도록 했습니다.
- **조회 화면** — Appsmith로 SQL을 몰라도 조건을 고르고 버튼을 누르면 조회·추출되는 화면을 만들었습니다. 실무자와 관리자 화면을 분리해 잘못된 수정과 데이터 유실을 막았습니다.
- **정착** — 사용 매뉴얼을 전사에 공유하고, 새로 온 팀원과 함께 유지보수·커스터마이징 가이드를 정리했습니다.

## 결과

- 평균 조회 시간 **12초 → 1~2초**
- 데이터 운영 리소스 **약 30% 절감**
- 고객 데이터를 빨리 찾게 되면서 고객서비스팀 응대 속도 **약 1.5배**
- 스프레드시트 수기 운영 → MySQL 기반 운영으로 전환

## 배운 점

운영 효율은 한 사람의 속도를 높일 때보다, **필요한 정보가 필요한 사람에게 자연스럽게 닿는 구조**를 만들 때 크게 좋아진다는 것을 배웠습니다. 그리고 시스템은 만든 순간이 아니라, 만든 사람이 없어도 계속 쓰일 때 완성된다는 것도요.
